# MailMind v0.4：附件解析與唯讀 MCP Tools

> **版本定位**：這是基於 v0.3 的增量更新，保留 Gmail → Gemini → LINE 自動摘要／推播。新增「**新郵件**附件解析」與「**本機 stdio MCP Server**」。目前 LINE 聊天室**尚未**接入 MCP 問答 Agent，這是後續階段。

## 1. 功能對照

| 項目 | v0.4 | 備註 |
|---|---|---|
| PDF | ✅ 擷取可選取的文字 | 前 12 頁，掃描版無 OCR |
| DOCX | ✅ 解析段落與表格 | 不執行文件內巨集 |
| PNG/JPG | ✅ 格式檢查、基本資訊 | 使用 Gemini 圖片內容辨識需自行啟用 |
| 與郵件一起摘要 | ✅ | 已擷取的文字會併入摘要 Context |
| MCP 搜尋郵件與讀取摘要 | ✅ | 讀取既有 SQLite 資料 |
| MCP 查詢附件及擷取結果 | ✅ | 不提供任意檔案路徑 |
| LINE 主動推播 | ✅ | 沿用 v0.3 的 Worker |
| LINE 對話中主動詢問歷史郵件 | 尚未 | 下一階段 Agent/MCP Client |
| XLSX／掃描 PDF OCR | 尚未 | 後續擴充 |

**隱私重點**：後端不會保存原始二進位附件，只在 SQLite 儲存檔名、檔案類型、狀態、與擷取文字。PDF/DOCX 文字會併入既有 Gemini 摘要輸入；若設定圖片辨識 `true`，圖片位元組也會傳到 Gemini API，可能涉及免費 API 的資料使用政策。請只在同意且信件適合的情況下啟用。

## 2. 在 HPC 升級

先把 `MailMind-v0.4-patch.zip` 上傳到 `~/MailMind/`。保持現有 `.env` 與 `data/mailmind.db` 不被覆蓋。

```bash
cd ~/MailMind
source .venv/bin/activate

# 備份程式、DB、Apps Script（遠端編輯器中的 Code.gs 也請另存一份）
cp -a app app.backup.before-v04
cp data/mailmind.db data/mailmind.db.before-v04
cp apps_script/Code.gs apps_script/Code.gs.before-v04

unzip -o MailMind-v0.4-patch.zip -d .
python -m pip install -r requirements.txt
python -m scripts.check_setup
pytest -q
```

`check_setup` 應會列出新資料表 `email_attachments`。使用的是新增資料表的方式，既有 Email / LINE 資料不需要重建。若升級期間有 Worker 同時寫入 SQLite，請先暫停寫入再備份，或用 SQLite backup API 做一致性備份。

新版模型設定仍沿用先前可用的 `GEMINI_MODEL`，不要覆蓋你自己的 `.env`。可以**額外**加上：

```ini
MAILMIND_ENABLE_IMAGE_ANALYSIS=false
MAILMIND_MCP_ACCOUNT_ID=你的 ACCOUNT_ID
```

編輯後，在 `MailMind` 的 tmux session 重新啟動 Uvicorn（使用 v0.3 原本的啟動方式即可）：

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

確認（另外一個 Terminal）：

```bash
curl http://127.0.0.1:8000/health
# version 應是 0.4.0
```

電費機器人 Flask、Cloudflare Tunnel、LINE Worker **均不需要換路由或修改程式**。

## 3. 更新 Google Apps Script

需要**手動到 Google Apps Script 編輯器**，用新的 `apps_script/Code.gs` 內容取代雲端專案的 `Code.gs`。僅更新 HPC 上的檔案不會自動更新 Google 端。請先備份舊版，並保留原來的 `Script Properties`：

- `BACKEND_URL`（原有 `/mailmind` 前綴不變）
- `ACCOUNT_ID`
- `INGEST_TOKEN`
- `START_AT_ISO` / `SUCCESS_IDS`（既有監控時間與去重紀錄，不要清空）

新函式 `mmAttachments_` 在送信時擷取 **最多 3 份** PDF、DOCX、PNG、JPG/JPEG（單檔 ≤ 2 MiB、總原始大小 ≤ 4 MiB），不含 inline images；超額或格式不支援者記錄略過原因，避免意外處理大型郵件。限制是為了 Side Project 的額度、記憶體與連線穩定性，並不是 Gmail 本身的附件限制。

更新後先手動執行 `mmScanInbox()`，再用其他信箱寄**一封新的**、附小型文字 PDF 或 DOCX 的測試信。已處理過的舊信不會自動再次匯入附件；不應重設監控起始時間來補抓整個信箱。

## 4. 查驗附件是否進資料庫

```bash
cd ~/MailMind
python - <<'PY'
import sqlite3
with sqlite3.connect('data/mailmind.db') as db:
    rows = db.execute('''
        SELECT e.subject, a.filename, a.status,
               LENGTH(a.extracted_text), a.note
        FROM email_attachments a
        JOIN emails e ON e.id = a.email_id
        ORDER BY a.created_at DESC LIMIT 10
    ''').fetchall()
for subject, filename, status, chars, note in rows:
    print(f'{subject[:40]} | {filename} | {status} | {chars} 字 | {note}')
PY
```

`extracted`：成功擷取可用內容。`metadata_only`：已辨識附件類型，但沒有可用的文字（例如未啟用圖片辨識、或掃描版 PDF）。`error`：格式損壞或解析失敗；這封信的純文字仍可正常摘要。

## 5. MCP Tools 的功能與測試

MCP Server 以 Python SDK **2.x** 實作，使用 **stdio**。它只讀取**一個指定 Gmail Account ID** 的郵件和附件結果，不具備任意檔案讀取或寫入權限，也不會直接對外發布 HTTP Endpoint。

| Tool | 功能 |
|---|---|
| `search_emails(keyword, limit)` | 搜尋該信箱中的主旨、寄件者與已儲存摘要，最多 20 筆 |
| `get_email_summary(email_id)` | 讀取指定郵件摘要 |
| `list_email_attachments(email_id)` | 列出該郵件附件及處理結果 |
| `read_attachment_text(attachment_id)` | 讀取該附件已擷取的文字或圖片辨識結果 |

### 不接 MCP Client 也能先驗證（推薦）

原先 `scripts.create_account` 的輸出含 `ACCOUNT_ID`，如果當時沒保存，可在自己的 HPC 透過 SQLite 查詢：

```bash
python - <<'PY'
import sqlite3
with sqlite3.connect('data/mailmind.db') as db:
    for account_id, address in db.execute('SELECT id, address FROM email_accounts'):
        print(account_id, address)
PY
```

接著（將 UUID 換成實際帳號）：

```bash
python -m scripts.demo_mcp_tools \
  --account-id '你的 ACCOUNT_ID' \
  --keyword 'MailMind'
```

此指令直接呼叫 MCP 背後的**同一組工具邏輯**。如果查得到郵件、附件名稱，就表示資料、帳號隔離與解析流程已串接；但不代表 MCP 協定層已完成測試。

### 啟動 stdio MCP Server

先在 `.env` 設定 `MAILMIND_MCP_ACCOUNT_ID`，然後用**支援 MCP 的本機 Client** 把這個命令設為 MCP Server：

```bash
/home/你的使用者名稱/MailMind/scripts/start_mcp.sh
```

示意配置（每種 MCP Client 的設定格式不同）：

```json
{
  "mcpServers": {
    "mailmind": {
      "command": "/實際絕對路徑/MailMind/scripts/start_mcp.sh"
    }
  }
}
```

注意：**HPC 上的 stdio MCP Server 不會因為啟動而自動出現在你自己電腦的 ChatGPT／LINE**。MCP Client 必須在可以啟動該命令、讀取相同資料庫的執行環境，或後續另建通過認證的遠端傳輸。如果是桌面 Client 在本機、MailMind 在 HPC，不能把 HPC 的本機路徑直接填進桌面設定。

不要把 MCP Server 掛到既有的 Cloudflare Quick Tunnel。將來真的需要遠端 MCP，需另外設計使用者認證、權限與隔離，而不是把 SQLite 查詢直接對外公開。

## 6. 測試、維運、故障排除

```bash
pytest -q
python -m scripts.check_setup
python -m scripts.send_pending_line --dry-run
```

- Gmail 新信有摘要卻沒有附件：確認 Apps Script **網頁版** `Code.gs` 已更新；單純解壓縮 ZIP 不會更新 Google 端。
- PDF 回傳 `metadata_only`：可能是掃描版，尚未支援 PDF OCR。
- 圖片只有尺寸沒有文字：預設不對雲端做圖片辨識，確認隱私後才能設 `MAILMIND_ENABLE_IMAGE_ANALYSIS=true` 並重啟 Uvicorn。
- `ModuleNotFoundError: mcp`：確認啟用專案 `.venv` 後執行 `python -m pip install -r requirements.txt`。
- MCP Client 沒回應：stdio Server 的 stdout 只能傳 MCP 協定訊息，勿在啟動腳本額外 `echo`。
- 舊 Gmail 未補入附件：原本郵件 ID 已成功去重；這是刻意的相容性行為，不是遺失資料。
- 免費額度：一次郵件摘要仍受 `MAX_DAILY_SUMMARIES` 限制；啟用圖片解析會增加 Gemini API 呼叫數。

## 7. 已知限制與下一階段

1. 本版本不提供 LINE 端主動問答。下一階段將由 LINE Bot → Agent → MCP Client → Tools 形成完整互動鏈。
2. 目前每個 stdio MCP Process 固定對應**單一 Account ID**；正式多人遠端 MCP 需要獨立授權與會話隔離。
3. PDF 只讀可擷取文字，掃描件的 OCR、更多 MIME 類型與壓縮檔均尚未實作。
4. 原始附件不留存，MCP 只能讀到當時抽出的文字；後續想重新辨識時需要重新取得 Gmail 附件。
5. SDK 2.x 的協定層請在你自己的 `.venv` 實際安裝後，用 MCP Inspector／Client 再做一次 end-to-end 驗證。
