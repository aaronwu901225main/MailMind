# MailMind v0.5.1：Knowledge Chunks + SQLite FTS5 全文檢索

> **定位**：v0.4 的增量更新。不包含向量 Embedding、Hybrid RAG、LINE 即時問答或歷史 Gmail 雲端回抓。先讓資料索引與帳號隔離可靠，再做 v0.5.2。
>
> **費用**：完全使用本地 SQLite 與現有 Python 套件；索引本身不呼叫 Gemini，不使用 GPU，無額外 API 費用。

## 1. 新增的功能

| 項目 | v0.5.1 |
|---|---|
| 新收到的 Email 內文 | 存入分段的 `knowledge_chunks`，可全文搜尋（原本 v0.4 沒有保存內文） |
| 既有 Email | 從 `emails.subject/sender`、`summaries.content` 與 `email_attachments.extracted_text` 回填索引 |
| FTS5 trigram | 中文／英文的關鍵字全文索引、BM25 排序 |
| 短字搜尋 | 對少於 3 字元的詞（如 `AI`）使用有帳號範圍的 SQL 子字串查詢 |
| 來源追溯 | 每個片段保存 `email_id`、`source_type`、`source_id`、`chunk_index`；附件片段帶檔名 |
| MCP | 保留 v0.4 的 4 個工具，新增 `search_knowledge(keyword, limit)` |
| 多使用者隔離 | 從 MCP 程序預先授權的 `MAILMIND_MCP_ACCOUNT_ID` 固定範圍查詢 |
| Gmail → Gemini → LINE | 保留原本流程；若知識索引失敗，仍可成功收信與推播，之後再補索引 |

### 重要限制

- **v0.4 沒有持久化舊 Email 的完整本文**。回填僅能使用 DB 已保存的摘要、寄件者、主旨與附件文字。v0.5.1 **新信**才會完整保留已傳入（最長 12,000 字元）的內文索引。
- 本版不會主動從 Gmail 抓取 5 年前的信，也不會向 LINE 推播所有舊信。
- PDF 文字仍只來自 v0.4 的附件擷取結果，掃描 PDF 若未做 OCR 就沒有文字可索引。
- 本版是**詞彙／子字串檢索，不是語意向量 RAG**。同義詞、語意改寫與跨多封推理，留到 v0.5.2 和 v0.5.3。
- 關鍵字搜尋的 `score` 僅表示 FTS BM25 排序，**不是可靠度百分比**。

## 2. 升級前備份

在 HPC 的 `~/MailMind` 專案根目錄執行，先確認不是同時有兩支 MailMind Uvicorn 服務。維護時建議先短暫停止 `MailMind` tmux 內的 Uvicorn；電費機器人和 Cloudflare Tunnel **不需要修改**。Gmail Apps Script 若剛好觸發，短暫連線失敗請之後重新掃描確認補送。

```bash
cd ~/MailMind
source .venv/bin/activate

cp -a app app.backup.before-v051
cp -a scripts scripts.backup.before-v051

# SQLite 線上一致性備份，比直接複製仍有寫入的 DB 安全
python - <<'PY'
import sqlite3
from pathlib import Path
source = Path('data/mailmind.db')
if not source.exists():
    raise SystemExit(f'找不到資料庫：{source}')
with sqlite3.connect(str(source)) as db:
    with sqlite3.connect('data/mailmind.db.before-v051') as backup:
        db.backup(backup)
print('資料庫備份完成')
PY
```

請將檔案 `MailMind-v0.5.1-FTS-patch.zip` 上傳到 `~/MailMind/` 後再執行：

```bash
unzip -o MailMind-v0.5.1-FTS-patch.zip -d .
python -m scripts.check_knowledge_fts
python -m scripts.check_setup
pytest -q
```

預期至少新的 `tests/test_knowledge.py` 會通過。若你自己的 Python/SQLite 不支援 FTS5 trigram，搜尋仍有 SQL 逐筆比對的備援，但較慢；此時不建議立刻用大量歷史郵件測試。

**不需要**重新設定 Gemini API Key、LINE Channel、Google Apps Script、Cloudflare Tunnel，也不需要更改 `.env`。

## 3. 回填已在 SQLite 的郵件

從 `scripts.create_account` 先前產生的 `ACCOUNT_ID` 取回 UUID。如果忘記，可以在本機的 HPC 上執行：

```bash
python - <<'PY'
import sqlite3
with sqlite3.connect('data/mailmind.db') as db:
    for account_id, address in db.execute('SELECT id, address FROM email_accounts'):
        print(account_id, address)
PY
```

對你的帳號回填：

```bash
python -m scripts.build_knowledge_index \
  --account-id '你的ACCOUNT_ID' \
  --batch-size 50
```

說明：
- 使用既有 SQLite 保存的資料，不會呼叫 Gemini、LINE、Gmail，不會增加 API 費用。
- 可重複執行，內容完全相同的 Chunk 不會重新建立。
- 只更新 metadata／summary／attachment 來源，不會刪除新版新郵件的 body Chunks。
- 若有多位使用者，請對每個 `ACCOUNT_ID` 分別執行；不會混查其他人的資料。

## 4. 先用 CLI 測試繁體中文與附件文字

```bash
python -m scripts.search_knowledge \
  --account-id '你的ACCOUNT_ID' \
  --keyword 'ATTACH-VERIFY-8294' \
  --limit 10

python -m scripts.search_knowledge \
  --account-id '你的ACCOUNT_ID' \
  --keyword '解析成功率' \
  --limit 10

python -m scripts.search_knowledge \
  --account-id '你的ACCOUNT_ID' \
  --keyword 'AI'
```

查到的結果會標示 `[attachment]`、`[summary]`、`[body]` 或 `[metadata]`，並包含原始 Email ID 與相關片段。這些搜尋只在本機執行，不會把內容上傳給 LLM。

## 5. 啟動 MailMind v0.5.1 並驗證新郵件自動索引

在原本 `MailMind` tmux 中重新啟動 Uvicorn：

```bash
cd ~/MailMind
source .venv/bin/activate
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另外的 Terminal 檢查：

```bash
curl http://127.0.0.1:8000/health
# {"status":"ok","service":"MailMind","version":"0.5.1"}
```

接著由另一個 Email 帳號寄**全新測試信**，並放入只在本文出現的辨識碼，例如 `BODY-7319`。等 Apps Script 掃描和 LINE 推播完成後，執行：

```bash
python -m scripts.search_knowledge \
  --account-id '你的ACCOUNT_ID' \
  --keyword 'BODY-7319'
```

期待有 `[body]` 的搜尋結果，表示**不只是 Gemini 摘要**，連原始新郵件內文也已經索引。

如果新信已完成摘要卻查不到 `[body]`，請檢查 Uvicorn 日誌是否出現 `Knowledge indexing failed`，然後貼**去除個資與 Token**的錯誤訊息。正常收到 Email 與 LINE 摘要不應受索引故障影響。

## 6. MCP：第五個工具 `search_knowledge`

`.env` 繼續使用：

```ini
MAILMIND_MCP_ACCOUNT_ID=你要授權給本機MCP程序的ACCOUNT_ID
```

在同一台有 MailMind DB 的 HPC 上，使用先前成功的 MCP Client 驗證：

```bash
python - <<'PY'
import asyncio
import sys
from mcp import Client, StdioServerParameters

async def main():
    params = StdioServerParameters(command=sys.executable, args=['-m', 'app.mcp_server'])
    async with Client(params) as client:
        tools = await client.list_tools()
        print([tool.name for tool in tools.tools])
        result = await client.call_tool('search_knowledge', {
            'keyword': 'ATTACH-VERIFY-8294', 'limit': 5,
        })
        print('is_error:', result.is_error)
        for item in result.content:
            if item.type == 'text':
                print(item.text[:2000])

asyncio.run(main())
PY
```

預期會有原來 4 個工具加上 `search_knowledge`，且 `is_error` 為 `False`。此時 MCP stdio 程序仍限於 `.env` 指定的單一帳號，不可直接公開到現有的 Cloudflare Quick Tunnel。

## 7. 回復方法與限制

如果升級失敗：停止 MailMind Uvicorn，將 `app.backup.before-v051` 的內容複製回 `app/`，以備份的 SQLite DB 回復；**不建議對已經有新郵件寫入的 DB 直接還原舊備份**，否則會失去升級後新收到的郵件。可先保留新版 DB 另行調查。其他 tmux 程序不需要修改。

新增資料：`knowledge_chunks`（ORM 表）與 `knowledge_fts`（SQLite FTS5 虛擬表及維護 triggers）。請勿手動刪除後者；若真的需要重建索引，可以在資料庫一致性備份後進行 FTS `rebuild`。

處理私人郵件時，索引資料與備份檔同樣屬於敏感資訊，請保持檔案權限限制，避免公開到 GitHub。
