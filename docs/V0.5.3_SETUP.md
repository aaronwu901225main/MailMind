# MailMind v0.5.3：LINE + MCP + Gemini 郵件問答 Agent

> **基礎版本**：已驗收 v0.5.2.1（包含 `search_relevant_emails` MCP Tool）。
> **重要**：本 ZIP 是增量檔，不是整個專案；**不會覆寫**原本的 `app/routes/line_webhook.py`、
> `scripts/send_pending_line.py`、電費機器人 Flask `app.py`、`.env` 或 `data/mailmind.db`。
> **可用性**：本地還原測試環境 39 個離線測試通過；實際 LINE、HPC MCP/Gemini API 和公開 webhook 必須由你端驗收。

## 0. 這次新增什麼

| 模組 | 實際行為 |
| --- | --- |
| LINE 指令入口 | `查郵件 <問題>` / `問郵件 <問題>`；其他指令交回舊 webhook |
| 代理路由 | 新增 FastAPI `POST /line/agent/webhook`；須手動修改**電費 Flask 代理內部轉送目的地** |
| LINE 簽章 | 用 `MAILMIND_LINE_CHANNEL_SECRET` 驗證 HMAC SHA256，未通過拒絕 |
| SQLite queue | `line_agent_jobs` 新資料表；LINE webhookEventId/message ID 去重；預設 5 次／日／使用者 |
| MCP Client | 背景 Worker 以 `mcp.Client(StdioServerParameters(...))` 啟動現有 MCP Server，**每題以綁定的 Account ID 隔離** |
| 檢索 | `search_relevant_emails`，Worker 強制開啟 Gemini Re-rank，**只接收相關且有合法證據的 Chunk** |
| 回答 | Gemini 用實際 Chunk 提供繁體中文回答；回覆附上 SQLite 確認的來源郵件主旨 |
| LINE 回覆 | webhook 用 reply token 立即確認，Worker 再用 Push API 回答；附穩定 `X-Line-Retry-Key` |
| 資料節制 | 不存原始附件；寄給 Gemini 前做基本的 email、帶 token 的 URL、手機與憑證字串遮罩 |

**注意：** 這是「受限、可驗證的單回合 Agent」：不是由 LLM 任意挑選／執行七個 MCP 工具。Agent 只呼叫 `search_relevant_emails`，不開放寫信、刪信、任意 SQL、任意路徑或 Shell。複雜多步驟工具規劃可留到 v0.5.4。

## 1. 安裝前先備份

在 `MailMind` tmux 暫停 Uvicorn；仍使用現有 `.venv`。建議暫停其他 MailMind 寫入者再做 SQLite 一致性備份：

```bash
cd ~/MailMind
source .venv/bin/activate
cp -a app app.backup.before-v053
cp -a scripts scripts.backup.before-v053

python - <<'PY'
import sqlite3
from pathlib import Path
src = Path('data/mailmind.db')
dst = Path('data/mailmind.db.before-v053')
with sqlite3.connect(src) as a, sqlite3.connect(dst) as b:
    a.backup(b)
print('✅ SQLite 備份完成')
PY
```

把 ZIP 上傳到 `~/MailMind/`，執行：

```bash
unzip -o MailMind-v0.5.3-LINE-Agent-patch.zip -d .
python -m compileall -q app scripts
pytest -q
python -m scripts.check_setup
python -m scripts.check_agent
```

**應新增 `line_agent_jobs` 資料表**。它由既有 `init_database()` 的 `Base.metadata.create_all()` 建立，不會清掉先前的郵件、摘要、320 個 Embedding 或 LINE 綁定。

## 2. 明確開啟服務、隱私與額度設定

在 `~/MailMind/.env` **附加**以下設定，不要覆寫已經存在的 LINE Token 或 GEMINI_API_KEY：

```ini
# 未設定時兩者為 false；必須明確同意雲端處理郵件摘要/附件節錄。
MAILMIND_AGENT_ENABLED=true
MAILMIND_AGENT_ALLOW_CLOUD_EMAIL=true

# HPC 登入節點建議 false：FTS5 + 查詢擴展 + Gemini Rerank 已可用。
# 只有在學校允許推論的計算節點才打開 true 使用 E5。
MAILMIND_AGENT_USE_SEMANTIC=false

# 保守的免費額度防護
MAILMIND_AGENT_DAILY_LIMIT=5
MAILMIND_AGENT_MONTHLY_PUSH_LIMIT=20
MAILMIND_AGENT_MAX_QUEUE=20
```

**雲端隱私警告**：問答使用既有 Gemini API 進行 Reranking + 回答，每題通常需要兩次 Gemini 呼叫。郵件候選內容在上傳前會做**有限的格式遮罩**，這不是完整的個資消除或 DLP 系統。含機密、醫療、人事、財務敏感資料的帳號不適合在未經許可下啟用；請確認 Gemini API 免費層級的隱私條款和剩餘額度。

本版使用者可以綁定多個 Gmail Account，但**Agent 問答要求該 LINE 使用者恰好對應一個 EmailAccount**；如果有多個會拒絕查詢，不會私自選第一個。暫不支援 LINE 群組查詢，避免帳號資訊回到公開聊天室。

## 4. 先測真正的 MCP + Gemini 問答（**不會送 LINE**）

在你允許執行的環境測試，避免在登入節點載入 E5（目前設定 `MAILMIND_AGENT_USE_SEMANTIC=false`）。

```bash
cd ~/MailMind
source .venv/bin/activate
python -m scripts.agent_demo \
  --account-id '你的ACCOUNT_ID' \
  --query 'PDF 文字辨識失敗的原因是什麼？'
```

這會以 MCP stdio 查詢 `search_relevant_emails`，並使用 Gemini 產生一段帶來源的回答，但**不會送到 LINE**。應該只引用你的 PDF 測試報告；如果沒有被 Rerank 判斷相關的有效證據，就回覆「找不到足夠相關的郵件證據」。

## 5. 開啟獨立 Agent Worker

使用**新的 tmux**，不要停掉既有 `mailmind-line`（它是寄送新信摘要的 Worker）。

```bash
cd ~/MailMind
source .venv/bin/activate
python -m scripts.agent_worker --once --dry-run

# 開新的專用 tmux
# tmux new -s mailmind-agent
python -m scripts.agent_worker --loop --interval 15
```

上述 `tmux new` 要在一般 shell 執行；也可以先開 `tmux new -s mailmind-agent`，再於 session 中啟動 Worker。它從 SQLite 取工作，不會在 LINE Webhook 裡執行 Embedding/Gemini。若開啟 `MAILMIND_AGENT_USE_SEMANTIC=true`，**整個 Worker 必須在允許 CPU 推論的計算環境執行**，且該環境必須能讀到相同 SQLite 與模型快取。

> `--once --dry-run` 只檢查佇列，不會修改工作、不呼叫 Gemini，也不會送 LINE。

## 6. 最後修改電費 Flask 代理的「內部目標」

先找到你現有的 Flask `app.py` 中，處理 `@app.route('/mailmind/line/webhook', methods=['POST'])` 的程式。**不要覆寫整份 Flask app.py**；電費機器人的路由和 Scheduler 都要保留。

它原本應該是大致類似這樣：

```python
requests.post(
    f"{MAILMIND_URL}/line/webhook",    # 舊路徑
    data=request.get_data(),
    headers={
        'Content-Type': 'application/json',
        'X-Line-Signature': request.headers.get('X-Line-Signature', ''),
    },
    timeout=15,
)
```

**只改內部目的地字串**：

```python
f"{MAILMIND_URL}/line/agent/webhook"   # 新路徑
```

原本外部 webhook URL **完全不改**，仍是：

```text
https://你的-ngrok-或-cloudflare-網域/mailmind/line/webhook
```

必須確認 Flask **把原始 request body 和 `X-Line-Signature` 原樣轉送**，不可自行重新編碼外部 payload，否則 FastAPI 的簽章驗證會失敗。新入口只處理 `查郵件 / 問郵件`，其餘訊息會重新簽署並轉交原本的 `http://127.0.0.1:8000/line/webhook`，原本的「綁定」「完整」「我的設定」路由不受覆寫。

**這是本版與 v0.5.2.1 最大的部署不同**：修改 Flask 程式後，需要**重新啟動 Flask 電費 Bot 那個 tmux 裡的 Waitress** 讓代理路由生效。ngrok/Cloudflare tunnel 不需要重新建立；只要維持原本指向 Flask 的連線即可。

如果你現有的代理寫法不同，請先確認它的原始程式，再調整這一行，**不要直接取代整個 webhook 處理函式**。

## 7. LINE 驗收順序

1. LINE Developers Console Verify：應回 200。
2. 在 MailMind LINE Bot 輸入「我的設定」：應看到原本設定資訊。
3. 輸入「查郵件 PDF 文字辨識失敗的原因是什麼？」：應立即收到「已收到查詢」，稍後獨立 Push 回覆。
4. 回答應該引用 `【MailMind 測試】v0.4 PDF 附件解析與專案報告`，說明 5 份掃描式 PDF 缺少可擷取的文字層、未啟用 OCR，解析率 96.0% 未達 98.0%。
5. 詢問明顯不存在的資訊：應得到沒有足夠相關證據的回答，而不是亂引其他信。
6. 在 Terminal：`python -m scripts.check_agent`，確認 `sent` 增加；LINE Worker 未中斷自動摘要推播。

**預期情況，非你目前已實測的結果**：部署是否正常需要以你 HPC 的 LINE 訊息和 Worker 輸出驗證。

## 8. 重試、額度與已知限制

- LINE 可能重送同一 webhook：以 `webhookEventId`／message ID 的 SHA256 去重，不會重複建立問答工作。這**不是**根據 Email 內容去重；原本 Gmail Message ID 規則維持不變。
- LINE Push API 使用固定 `X-Line-Retry-Key`；逾時重試可避免被 LINE 重複接受。參考：<https://developers.line.biz/en/docs/messaging-api/retrying-api-request/>。
- 新增 `line_agent_jobs` 保存問題及回答，以便 Worker 重試；推播成功後即清除問題與結果文字，保留匿名事件雜湊與狀態供去重／額度統計。失敗最多 3 次，未成功會退避重試。
- 本地 `MAX_LINE_PUSHES_PER_MONTH`、Agent 月額度和既有摘要 Push 狀態共同計算**保守預算**，但不是 LINE 伺服器端即時額度。各 Worker 同時送信可能競爭，仍需查看 LINE Official Account Manager 的實際訊息用量。
- 查詢結果僅含 `relevance=relevant` 且有合法 Chunk 來源的片段；回答可能因 Gemini 誤判而不完整，請回看原始郵件做重要決策。
- Worker 目前是單次呼叫固定的 `search_relevant_emails` Tool，再作回答生成。未支援工具自主規劃、持續對話、多帳號、群組問答或 OCR。
- 如果 Worker 啟動時 `.env` 隱私同意設為 false，**會拒絕處理**。請不要透過環境變數繞過帳號綁定。
- `pip install mcp>=2,<3 google-genai>=1 httpx` 應已由你原有 v0.4 requirements 安裝；這次無需新套件。

## 9. 回復舊版（不刪除任何郵件）

若 LINE「我的設定」等既有指令異常，**先把 Flask 代理內部目標改回 `/line/webhook`，並重新啟動 Waitress**。這能立刻切回已驗證的舊 LINE 路由，不會影響 Gmail 摘要及 LINE Worker。確認後再停止 `mailmind-agent`。

需完整回復 v0.5.2.1 時，停止 Uvicorn，復原 `app.backup.before-v053` 和 `scripts.backup.before-v053`；SQLite 的新 `line_agent_jobs` 表可留著，不會阻礙舊版。**不要把備份 SQLite 覆蓋仍有新郵件寫入的正式資料庫**，以免遺失期間收到的信件。
