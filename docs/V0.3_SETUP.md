# MailMind v0.3: LINE Bot 設定與安全推播

## 原則

- **另建 MailMind 的 LINE 官方帳號**，不與電費機器人共用 LINE Channel Token。仍沿用同一條 Cloudflare Tunnel。
- 每個 Gmail 使用者透過一次性 15 分鐘綁定碼，綁到自己的 LINE userId。
- 綁定前已存在的郵件記錄為 skipped，不會突然全部推播。
- 摘要長度可透過 LINE 傳「極簡」「中等」「完整」，對下一封新郵件生效。
- LINE reply 不消耗主動推播免費則數，push 會。預設保守上限 150 則/月，並在推播前查 LINE 官方額度。

## A. 安裝 MailMind 更新包

```bash
cd ~/MailMind
cp -a app app.backup.before-v03
unzip -o MailMind-v0.3-patch.zip -d .
# 注意：若 .env 已存在，不會在這包內覆蓋；參考 .env.v03.example 合併新欄位
pytest -q
python -m scripts.check_setup
```

將以下欄位加到 **MailMind 的** `.env`，不是電費機器人的 `.env`：

```ini
MAILMIND_LINE_CHANNEL_SECRET=新的_MailMind_Channel_Secret
MAILMIND_LINE_CHANNEL_ACCESS_TOKEN=新的_MailMind_Channel_Access_Token
MAX_LINE_PUSHES_PER_MONTH=150
```

## B. 建立獨立 LINE 官方帳號

開啟 https://manager.line.biz/ 建立新的 MailMind 官方帳號，依 LINE Developers Console 開通 Messaging API，取得此帳號的 `Channel secret` 與 `Channel access token`。

LINE Developers 的 Webhook URL 設為：

```
https://instance-not-nurse-eligibility.trycloudflare.com/mailmind/line/webhook
```

不要改動電費機器人原有的 `/webhook`。啟用 `Use webhook`；必要時關閉 LINE OA 的自動回應以免與本機 Bot 重複答覆。

## C. 增加共用 Tunnel 的反向代理路由

請將更新包內 `docs/flask_line_proxy_snippet.py` 中的 route 加入電費機器人 app.py 的 `app.run()` 或 `main()` 前（原本反向代理 MailMind health/ingest 的路由旁）。**只增加這個路由**，不要覆蓋原本電費機器人的 `/webhook`。

重新啟動電費機器人 Flask/Waitress 與 MailMind FastAPI，`cloudflared` 不必重新啟動。先測試：

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:5000/mailmind/health
# 不帶 LINE 簽章回傳 401 是正常的，表示可達而且有驗證
curl -i -X POST https://instance-not-nurse-eligibility.trycloudflare.com/mailmind/line/webhook -H 'Content-Type: application/json' -d '{"events":[]}'
```

在 LINE Developers Console 的 Verify 按鈕執行 Webhook 驗證（合法簽章、空事件時預期 200）。

## D. 綁定 Gmail 帳號與 LINE

```bash
cd ~/MailMind
source .venv/bin/activate
python -m scripts.create_line_link --email '你的Gmail信箱'
```

會產生一組 15 分鐘有效的一次性代碼。加 MailMind 新官方帳號為好友，私訊：

```
綁定 <剛才產生的代碼>
```

預期回覆：「✅ 綁定完成」。再送「我的設定」、「極簡」、「中等」、「完整」測試回覆。

## E. 第一次主動推播

**先綁定，之後才從另一個帳號寄一封新的測試郵件**。等待 Gmail Apps Script 掃描到該郵件並存入 summaries；接著執行：

```bash
python -m scripts.send_pending_line --dry-run
python -m scripts.send_pending_line --once
```

觀察 MailMind LINE 聊天室是否收到摘要。再次執行 `--once` 不應重複推播。

測試成功後，**僅啟動一個**發送 worker，可用 tmux：

```bash
tmux new -s mailmind-line
cd ~/MailMind && source .venv/bin/activate
python -m scripts.send_pending_line --loop --interval 300
```

用 `Ctrl+B` 然後按 `D` 離開 tmux，讓程序繼續執行。

注意：LINE webhook 驗證與 Gmail API 都依賴 HPC／Flask／cloudflared 正常運行；tmux 不會在主機重開機後自行恢復。

## 權限、額度與限制

- 免費 LINE 官方帳號的月推播額度以 LINE 官方當期方案為準。程式額外用 `MAX_LINE_PUSHES_PER_MONTH` 保守限制。
- LINE 的 X-Line-Retry-Key 可降低 API 重試造成的重複推播；LINE 官方僅保留 24 小時，超時仍有極少數重複情境。
- 現階段只發送純文字摘要。附件讀取／MCP 留到 v0.4。
- `.env`、LINE Token、Gmail Token、綁定碼都不要貼到 GitHub 或聊天中。
- SQLite 是單機 side project 設計，worker **只能啟動一份**；要多台或多 Worker 時才改 PostgreSQL + queue。
- 之前 v0.2 的 Apps Script 依然是使用者自己授權 Gmail。多人架構已預留，但尚未提供自助註冊入口。
