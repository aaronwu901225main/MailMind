# MailMind v0.5.4.2：受控的 LINE 結構化統計路由

## 功能／限制

- LINE 保留 `查郵件 ` 或 `問郵件 ` 觸發前綴，`我的設定`、`完整` 等舊功能不變。
- Worker 新增確定性查詢路由：刷卡／信用卡消費的「總額、多少錢、幾筆、統計」在**有明確時間範圍**時，走 `aggregate_events` + `get_extraction_coverage`，皆為真正的 MCP Client（stdio），帳號由已綁定 LINE 身分決定。
- 可識別台灣時間的「這週／上週／本月／上個月／今天／昨天／最近7天／最近30天」，及 `YYYY-MM-DD` 單日、`YYYY-MM-DD 至 YYYY-MM-DD`（含結束日）的區間。沒有日期的消費統計會要求補充，不亂選時間。
- 其他問題維持 v0.5.3 RAG。**沒有增加通用的 LLM 自動工具呼叫**，避免任意 SQL、隱私洩漏或不可靠的財務結論。
- 結果直接由 SQLite 整數金額格式化，不送 Gemini 算數；TWD、USD、JPY 等分開計算。
- 若沒有符合條件的 `verified` 交易，回報「沒有可統計紀錄」，**絕不宣稱使用者花了 0 元**；維持資料不完整與授權通知可能和正式帳單不同的警告。
- 此次沒有資料表修改、沒有重新回填、沒有重建 FTS5 / Embeddings；仍使用 v0.5.4.1 的事件資料。
- 舊郵件未完整入庫、仍有 `chunks=0` 或尚未跑 `extract_events`，會直接影響統計覆蓋，這版不會偷偷替你補齊。

## 安裝

從 **v0.5.4.1 General Events** 升級；不要安裝較早的 `Extraction-Fix` 修正包。

1. 在 `MailMind` 停止 Uvicorn，並停止 `mailmind-agent` Worker，以免更新過程中使用混合版本。`mailmind-line` 和反向代理可以保留，若要 SQLite 備份請短暫暫停所有寫入 Worker。
2. 備份：
   ```bash
   cd ~/MailMind && source .venv/bin/activate
   cp -a app app.backup.before-v0542
   cp -a scripts scripts.backup.before-v0542
   python - <<'PY'
   import sqlite3
   with sqlite3.connect('data/mailmind.db') as source:
       with sqlite3.connect('data/mailmind.db.before-v0542') as target:
           source.backup(target)
   print('SQLite 備份成功')
   PY
   ```
3. 上傳增量包，套用：
   ```bash
   unzip -o MailMind-v0.5.4.2-Analytics-Router-patch.zip -d .
   python -m compileall -q app scripts
   python -m pytest -q
   python -m scripts.check_setup
   ```
4. **不觸發 API** 的路由預覽：
   ```bash
   python -m scripts.check_agent_router --query '我這週總共刷了多少錢？'
   python -m scripts.check_agent_router --query '上週信用卡消費總額是多少？'
   python -m scripts.check_agent_router --query 'PDF 文字辨識失敗的原因是什麼？'
   ```
5. 先用 CLI 實際 MCP 驗證，不推送 LINE：
   ```bash
   python -m scripts.agent_demo --account-id '你的ACCOUNT_ID' --query '我這週總共刷了多少錢？'
   python -m scripts.agent_demo --account-id '你的ACCOUNT_ID' --query '上週信用卡消費總額是多少？'
   ```
   這裡可不會再載入 E5 或呼叫 Gemini，會回傳 SQL 中目前已驗證交易的統計與覆蓋警告。
6. 重啟 `MailMind` tmux 的 Uvicorn，確認 `/health` 版本 `0.5.4.2`；**同時重啟 `mailmind-agent` tmux Worker**（新路由在 Worker，只有重啟 FastAPI 不夠）：
   ```bash
   python -m scripts.agent_worker --loop --interval 15
   ```
7. LINE 輸入：`查郵件 我這週總共刷了多少錢？`。預設仍要求前綴，直接輸入未加前綴的自然語言會交給舊 Bot。

## 預期輸出

以 2026-11-24 為例，`這週` 是 `2026-11-23` 至 `2026-11-30` **不含**，與 11/19、11/20、11/21、11/22 的資料不同。

如果本週沒有已驗證事件，應回傳「沒有可統計的刷卡通知，不能推論消費 0 元」。

如果要驗證之前已回填的 11/19 多筆彙整：

```bash
python -m scripts.agent_demo --account-id '你的ACCOUNT_ID' \
  --query '2026-11-19 刷卡總額多少？'
```

請先確認 11/19 那封已執行不含 `--preview` 的 `reprocess_event_emails`，否則它的三筆交易仍未儲存到結構化資料庫。若同日還有其他交易，SQL 顯示的是該日全部已驗證的交易，不保證剛好 NT$547。

## 安全與可用性

- 每個 MCP 子程序只有綁定帳號的 `MAILMIND_MCP_ACCOUNT_ID`，工具不可接收使用者自行指定的帳號 ID。
- 透過既有 SQLite `line_agent_jobs` 佇列、Webhook 去重、LINE Push Retry Key 與每日額度。
- 不採用 Gemini 判斷金融交易是否「真的入帳」；`purchase` 統計包含授權型消費通知，且不自動抵扣退款／取消交易。
- 目前沒有跨封交易對帳，沒有可信的「完整銀行帳單」語意。
- 本地測試覆蓋路由、帳號隔離、精確金額、空資料及舊 RAG 路徑；HPC 的完整 `pytest -q` 與真實 LINE 回覆仍須驗證。
