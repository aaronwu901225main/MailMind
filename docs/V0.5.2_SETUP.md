# MailMind v0.5.2：本地 Embedding + Hybrid Retrieval

> **增量更新**：適用已完成 v0.5.1（Knowledge Chunks + SQLite FTS5）的 MailMind。
> **不改動**：Gmail Message ID 去重、Apps Script、LINE Webhook、LINE Worker、Cloudflare、電費機器人。
> **定位**：此版完成檢索引擎，不包含 LINE 即時 Agent 問答（留待 v0.5.3）。

## 1. 功能與設計選擇

| 功能 | 實作 |
|---|---|
| 文字 Embedding | `intfloat/multilingual-e5-small`（本地 CPU，384 維） |
| 向量儲存 | 原有 SQLite 中新增 `knowledge_embeddings` 表；Float32 BLOB，不需另外開資料庫服務 |
| 向量搜尋 | NumPy cosine similarity（向量已正規化，直接內積）；候選上限預設 2000 |
| 關鍵字搜尋 | 沿用 FTS5 trigram / BM25 和短字詞備援 |
| 混合排序 | Reciprocal Rank Fusion（RRF，預設 k=60），不直接混加 BM25 與 cosine 數值 |
| MCP | 原五個工具不變，新增 `hybrid_search(query, limit)` |
| 向量批次建立 | 獨立 CLI；只有指定時才下載模型、計算 Embedding |
| 結果來源 | 回傳來源 Email ID、Chunk ID、來源類型、檔名與片段 |
| 多使用者 | SQL 嚴格依 `account_id` 過濾；MCP 仍由既有 `MAILMIND_MCP_ACCOUNT_ID` 決定 |
| 去重 | 維持 v0.5.1：Gmail Message ID 去重，並保留 body / summary / attachment 各自的 Chunk |

### 安全與成本

- **零付費 API**：下載免費開放權重後，嵌入及檢索完全在你選定的運算環境執行，不需要 HPC GPU 或線上 Embedding API。
- **不要在 HPC 登入節點長時間跑模型**。請在學校允許的計算節點、互動工作或自己的電腦執行批次任務。HPC 的排程器與資源額度仍可能有管理規範。
- `MAILMIND_ENABLE_SEMANTIC_QUERY=false` 是預設，這樣 Uvicorn 與 MCP 不會因為搜尋而偷偷載入模型；MCP `hybrid_search` 此時使用安全的 FTS-only 備援。
- `app/services/embedding_store.py` 只在明確的離線建索引或語意搜尋時載入 `sentence-transformers`，**Gmail 收信時不會跑 Embedding**。
- 模型第一次下載需網路；之後查詢的模型載入只使用本地快取，不會偷偷向 Hugging Face 下載。模型/套件安裝本身仍需要磁碟空間與 CPU/RAM。
- 郵件與附件文字、向量仍屬私人資料，SQLite、備份與本地模型快取要保持合宜權限；不要提交到 GitHub。

## 2. 升級與備份

先在現有 `MailMind` tmux 停止 Uvicorn，避免升級期間兩種程式版本並行。先不要動 `electricity`、`cloudflare` 或 `mailmind-line` 的 tmux。

```bash
cd ~/MailMind
source .venv/bin/activate
cp -a app app.backup.before-v052
cp -a scripts scripts.backup.before-v052
python - <<'PY'
import sqlite3
with sqlite3.connect('data/mailmind.db') as source:
    with sqlite3.connect('data/mailmind.db.before-v052') as backup:
        source.backup(backup)
print('✅ SQLite 備份完成')
PY
```

上傳 `MailMind-v0.5.2-Hybrid-RAG-patch.zip` 到專案根目錄後：

```bash
unzip -o MailMind-v0.5.2-Hybrid-RAG-patch.zip -d .
python -m scripts.check_setup
pytest -q
```

`app/models.py` 新增 `knowledge_embeddings`，`init_database()` 會透過既有 `Base.metadata.create_all()` 建立新表，不會刪除原來的 `knowledge_chunks` 或郵件資料。

`requirements.txt` **保持不變**。為了避免讓 FastAPI 強制安裝 PyTorch，CPU Embedding 使用獨立檔案 `requirements-embeddings.txt`。在允許使用模型的運算環境安裝：

```bash
python -m pip install -r requirements-embeddings.txt
```

模型與套件可能較大，初次安裝或下載時間取決於網路與配額；請先確認運算節點能使用網路、以及你的磁碟空間。

## 3. 在允許的 CPU 運算環境建立向量

先查詢需要處理多少 Chunks：

```bash
python -m scripts.check_embeddings --account-id '你的ACCOUNT_ID'
```

第一次只做 8 個 Chunks：

```bash
python -m scripts.build_embeddings \
  --account-id '你的ACCOUNT_ID' \
  --batch-size 8 \
  --max-chunks 8 \
  --allow-download
```

**`--allow-download` 只在首次需要下載權重時使用**，且應在你允許網路下載模型的運算環境執行。下載成功後，再次執行可以省略。

確定資源使用正常後，建立該信箱剩下的向量：

```bash
python -m scripts.build_embeddings \
  --account-id '你的ACCOUNT_ID' \
  --batch-size 8
```

每批寫入 SQLite 並提交，因此中斷時已完成部分不會消失；相同模型與內容雜湊的片段會自動跳過。**重建或編修過的 Chunk** 將被視為待更新，舊向量不會通過有效性檢查。

如果運算節點讀不到同一份 SQLite，請在受允許的位置安全地複製資料庫、建立向量、再協調同步回來；切勿覆蓋有新信持續寫入的正式資料庫。更好的部署方式是讓批次任務與線上服務共享受控資料目錄或安排短暫維護時段。

再確認：

```bash
python -m scripts.check_embeddings --account-id '你的ACCOUNT_ID'
```

## 4. 測試 FTS5 與 Hybrid

在能讀取模型快取、且**允許 CPU 推論**的環境：

```bash
# 舊版 FTS5 / BM25，不載入模型
python -m scripts.hybrid_search \
  --account-id '你的ACCOUNT_ID' \
  --query '模型資料標註計畫'

# Hybrid：FTS5 + 向量檢索 + RRF
python -m scripts.hybrid_search \
  --account-id '你的ACCOUNT_ID' \
  --query '模型資料標註計畫' \
  --semantic
```

檢查輸出中的 `via=fts5`、`via=vector` 或 `via=fts5,vector`。只有成功取得同一個帳號、同一模型、內容雜湊相同的向量，`--semantic` 才會有真正的語意檢索效果。

如果權重未快取、缺少套件或載入失敗，程式會記錄警告並退回 FTS-only；**不要把這種 fallback 誤認成 Hybrid 成功**。

向量搜尋是**精確的 NumPy 線性掃描**：預設取最多 2000 個較新的 Chunk 參與比較，最大可調至 5000；已足夠初期 257 個 Chunks 的專案，但不是可無限擴充的 ANN 向量資料庫。

調整上限可在 `.env`：

```ini
MAILMIND_EMBEDDING_MODEL=intfloat/multilingual-e5-small
MAILMIND_VECTOR_CANDIDATES=2000
# 預設不在本機 MCP / FastAPI 執行 CPU Query Embedding
MAILMIND_ENABLE_SEMANTIC_QUERY=false
```

`MAILMIND_EMBEDDING_MODEL` 更換後必須重建 Embedding，舊模型向量不會被當作新模型結果。

## 5. MCP 新增第六個工具

先保留 `MAILMIND_ENABLE_SEMANTIC_QUERY=false`，確認 MCP 工具註冊與 FTS fallback：

```bash
python - <<'PY'
import asyncio, sys
from mcp import Client, StdioServerParameters

async def main():
    params = StdioServerParameters(command=sys.executable, args=['-m', 'app.mcp_server'])
    async with Client(params) as client:
        tools = await client.list_tools()
        print([t.name for t in tools.tools])
        result = await client.call_tool('hybrid_search', {
            'query': 'RAG-INDEX-5729', 'limit': 5,
        })
        print('is_error:', result.is_error)
        for item in result.content:
            if item.type == 'text':
                print(item.text[:1200])

asyncio.run(main())
PY
```

應看到原五個工具，加上 `hybrid_search`；結果會帶 `retrieval_modes: ["fts5"]`。需要讓 MCP 使用真正的語意檢索時，才將 `.env` 改成：

```ini
MAILMIND_ENABLE_SEMANTIC_QUERY=true
```

**只在允許模型推論的主機上啟用它**，並重新啟動該 MCP 程序。Query Embedding 需要載入本地 CPU 模型；建議先在個人電腦或計算節點驗證資源使用。MCP 的帳號隔離仍然靠原本 `MAILMIND_MCP_ACCOUNT_ID`，不要暴露 MCP stdio 服務到 Cloudflare Tunnel。

## 6. 使用自己的問題比較檢索品質

請自行建立 `data/retrieval_eval.jsonl`（不要上傳 GitHub），每行一個 JSON：

```jsonl
{"query":"PDF 解析失敗的原因是什麼？","relevant_email_ids":["實際郵件UUID"]}
{"query":"模型評測報告截止日期","relevant_email_ids":["另一封郵件UUID"]}
```

同一份問題集執行：

```bash
python -m scripts.eval_retrieval \
  --account-id '你的ACCOUNT_ID' \
  --questions data/retrieval_eval.jsonl --k 5

python -m scripts.eval_retrieval \
  --account-id '你的ACCOUNT_ID' \
  --questions data/retrieval_eval.jsonl --k 5 --semantic
```

輸出 Recall@5 和 MRR@5。評估時以**不同 Email ID** 為單位去重，避免一封郵件有多個 Chunk 被重複算成多封相關郵件。建議之後擴充到 20～30 題，包含精確編號、同義詞、繁中/英文混合、跨郵件資訊與附件檢索。

## 7. 已知限制、恢復方式與下一步

- 新信仍先建立 `knowledge_chunks`；**不會自動建立向量**。若要讓最新郵件參與語意搜尋，請在允許的運算環境定期重新執行 `scripts.build_embeddings`。
- 不用向量的時候，FTS5 及 LINE 自動摘要功能應跟 v0.5.1 完全一樣；這是刻意設計的降級路線。
- 目前的 v0.5.1 Chunk 長度按字元切分，E5 最長輸入有 token 上限，特別長的片段可能被截斷；先觀察實際召回效果，再考慮下一輪調整 Chunking。
- 此版**不會替舊版缺失的原始 Gmail 本文補資料**，仍只能使用已存在的摘要與附件擷取文字。
- 此版還**不是 LINE 上的 RAG 問答 Agent**；LINE 仍按原本流程收到新郵件摘要。v0.5.3 才會加入提問、工具選擇、權限驗證與來源引用。
- 有異常時，先檢查 `MAILMIND_ENABLE_SEMANTIC_QUERY=false` 及是否恢復 FTS-only，無須立刻刪除資料表。必要時先停止 Uvicorn，再根據 `app.backup.before-v052` 恢復程式。回復資料庫前務必另外備份**升級後新收到的郵件**，不要直接覆蓋正在寫入的正式 DB。

### v0.5.2 的驗收標準

1. 原有全部測試通過，Gmail → Gemini → LINE 不變。
2. `check_embeddings` 能顯示 Index 完成數量。
3. FTS-only 與 Hybrid 對同一問題有可比較的檢索結果。
4. MCP 新增 `hybrid_search`，且原有五個工具可用。
5. 測試確認不同使用者無法跨帳號讀取向量搜尋結果。
6. 以標註問題比較 Recall@5、MRR@5，不能只靠幾個漂亮的示例宣稱品質提升。
