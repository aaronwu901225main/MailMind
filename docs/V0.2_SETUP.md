# MailMind v0.2：Gmail → FastAPI → Gemini → SQLite

v0.1 的 `.env`、`data/mailmind.db` 保留不動。v0.2 暫時**沒有 LINE 推播、附件、正式 Gmail OAuth**。

## 1. 將 patch 解壓到既有 MailMind 專案

將 `MailMind-v0.2-patch.zip` 放在 ~/MailMind/ 上層或下載目錄。

```bash
cd ~/MailMind
# 使用下載檔案的實際路徑，不要直接照貼不一定存在的名稱
unzip -o /path/to/MailMind-v0.2-patch.zip -d ~/MailMind
```

Patch 只含修改與新增的程式碼、文件，不含 `.env` 或資料庫，不需要重建虛擬環境。

確認 `.env` 中已有：

```ini
GEMINI_MODEL=gemini-3.5-flash-lite
MAX_DAILY_SUMMARIES=10
```

`MAX_DAILY_SUMMARIES` 是每位使用者每天最多**成功生成** 10 封摘要；失敗不計。每日採 UTC 日期。若未設定預設 10。

```bash
pytest -q
python -m scripts.check_setup
```

## 2. 在資料庫建立一個信箱帳號

```bash
python -m scripts.create_account --email your-gmail@gmail.com --level medium
```

記下畫面輸出的兩個值，不要貼在聊天或程式碼倉庫：
- `ACCOUNT_ID`：公開識別碼，代表這個已登記信箱。
- `INGEST_TOKEN`：**等同密碼**，只在這一次顯示，後端存 SHA-256 雜湊。

如果忘記 Token，可用 `--rotate` 重建（舊 Token 隨即失效）。

## 3. 本機端到端測試（不碰 Gmail）

Terminal A：
```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Terminal B：
```bash
read -r -p 'ACCOUNT_ID: ' MAILMIND_ACCOUNT_ID
read -r -s -p 'INGEST_TOKEN: ' MAILMIND_INGEST_TOKEN; echo
export MAILMIND_ACCOUNT_ID MAILMIND_INGEST_TOKEN
python -m scripts.send_test_email
python -m scripts.send_test_email
```

第一次預期 `status: completed`；第二次 `status: duplicate`（**不應再次呼叫 Gemini**）。

上述 `read` 不會把 Token 寫入 shell history；測試完成請執行 `unset MAILMIND_ACCOUNT_ID MAILMIND_INGEST_TOKEN`。

## 4. Apps Script 設定

前往 https://script.google.com 建立新專案，將 `apps_script/Code.gs` 整份貼到編輯器。

進入 Project Settings → Script Properties，設定：
- `BACKEND_URL` = **可從 Google 連線的 HTTPS URL**（例如自有網域，測試也可採獲准使用的 Cloudflare Tunnel）
- `ACCOUNT_ID` = 步驟 2 的 ACCOUNT_ID
- `INGEST_TOKEN` = 步驟 2 的 INGEST_TOKEN

App Script 在 Google 伺服器執行，無法連線到你的 `127.0.0.1:8000`。請先確保後端有安全且可連線的 HTTPS 位址。測試階段建議暫時只傳虛構信，不要馬上匯入私人信件。**在 HPC 登入節點公開服務前請先確認學校／叢集管理政策。**

依序操作：
1. 在 Apps Script 函式選單選 `mmInitialize` → Run，首次執行須授權 Gmail、外部 HTTP 請求等權限。
2. 選 `mmSendDemo` → Run，驗證 Apps Script → FastAPI → Gemini → DB 全流程。
3. 送一封新的測試郵件到自己的 Gmail。
4. 選 `mmScanInbox` → Run，確認後端處理新信；執行紀錄只有 ID 與狀態，正式摘要存 SQLite。
5. 確認通過後才選 `mmInstallTrigger` → Run，啟動每 5 分鐘的檢查。
6. 想停止時執行 `mmRemoveTrigger`。

Apps Script 的 `START_AT_ISO` 只會在 `mmInitialize` 首次設定；這能避免第一次掃描把舊信全丟給 LLM。要調整時間須自行管理 Script Properties。

## 測試預期與限制

- 這個版本**只擷取收件匣最近 2 天、前 80 個對話串**；高流量或長時間離線可能漏掉郵件，正式多用戶版會改為 Gmail history 增量同步。
- Gmail 一個 thread 有多封 message，逐封用 `GmailMessage.getId()` 去重，**不是只看未讀或 Thread ID**。
- 只取信件純文字前 12,000 字，附件要等 v0.4。不要拿機密、醫療、公司信件測試免費 Gemini API。
- `/api/v1/ingest/gmail` 要求 `X-MailMind-Token`，同帳號重送相同 message id 不會重複摘要。
- 狀態 `error` 會在後續呼叫重試；狀態 `processing` 暫時回 409，超過 10 分鐘可重試。App Script 會留下錯誤項目供下次檢查。
- 首次執行 Apps Script 會看到 Google 要求 Gmail 權限，因為原生 GmailApp 使用完整 Gmail 授權範圍；請只在自己的受信任 Script 專案中執行。
- 端點目前會將成功摘要回給 Apps Script（作為開發驗收），正式部署會改成僅回傳狀態。
- 目前 SQLite 中只保存信件的寄件者與主旨及摘要，不保存原文；失敗時須由 Gmail 再送一次。
